บทความ "Defer, Panic, and Recover" บนบล็อกทางการของ Go (เขียนโดย Andrew Gerrand) 
เป็นบทความระดับคลาสสิกที่อธิบายถึงกลไกการควบคุมการทำงาน (Control Flow) แบบพิเศษ 3 ตัวในภาษา Go 
ซึ่งทำหน้าที่คล้ายกับ try-catch-finally ในภาษาอื่นๆ แต่นำมาประยุกต์ใช้ในรูปแบบเฉพาะของ Go เอง

สรุปเนื้อหาหลักและหัวใจสำคัญของบทความนี้แยกตามหัวข้อได้ดังนี้ครับ
1. Defer (เลื่อนการทำงาน)
    defer ใช้สั่งให้ฟังก์ชันทำงาน "หลังจากที่ฟังก์ชันหลักทำงานเสร็จสิ้น"
     (ไม่ว่าจะจบแบบปกติหรือจบเพราะเกิด panic) มักใช้ทำความสะอาดคืนทรัพยากร (Cleanup)
      เช่น ปิดไฟล์ (f.Close()) หรือปลดล็อก Mutex (mu.Unlock())

    บทความได้สรุป กฎ 3 ข้อของ Defer ไว้ดังนี้:

    1.ประเมินค่าพารามิเตอร์ทันทีที่เจอคำสั่ง (Evaluated immediately):
      ค่าของตัวแปรที่ส่งเข้าฟังก์ชัน defer จะถูกบันทึกไว้ ณ วินาทีที่เจอคำสั่งนั้น ไม่ใช่ค่าตอนที่ฟังก์ชันจบ
    
       i := 0
       defer fmt.Println(i) // จะพิมพ์ 0 เสมอ แม้ i จะเปลี่ยนเป็น 1 ในภายหลัง
       i++
    2.ทำงานแบบ LIFO (Last In, First Out):
      หากมีคำสั่ง defer หลายตัวในฟังก์ชัน ตัวที่สั่งหลังสุดจะถูกทำงานก่อน (เข้าคิวด้านบนสุดเหมือนสแต็ก)
      // สั่ง defer 0, 1, 2, 3
      // ผลลัพธ์ตอนฟังก์ชันจบจะพิมพ์เรียงเป็น: 3 2 1 0
    3.สามารถอ่านและแก้ไขค่า Return (Named Return Values) ได้:
      defer สามารถเข้าถึงและปรับเปลี่ยนตัวแปรที่เป็น Named Return ได้หลังจากที่คำสั่ง return ในฟังก์ชันถูกเรียก

2. Panic (การหยุดทำงานเมื่อเกิดข้อยกเว้น)
    panic คือฟังก์ชันบิวต์อินที่ใช้ หยุดการทำงานปกติของโปรแกรม 
    เมื่อเกิดสภาวะผิดปกติร้ายแรง (เช่น Array Index Out of Range หรือสั่ง panic() เอง)

    พฤติกรรม: เมื่อฟังก์ชันสั่ง panic ฟังก์ชันนั้นจะหยุดรันทันที แต่จะ ไล่รันฟังก์ชัน defer 
    ทั้งหมดภายในฟังก์ชันนั้นก่อน จากนั้นจึงย้อนกลับไปทำแบบเดียวกันกับฟังก์ชันที่เรียกมันมา (Caller) ย้อนขึ้นไปเรื่อยๆ
    จนถึงฟังก์ชัน main หากไม่มีการดักจับ โปรแกรมจะ Crash พร้อมพิมพ์ Stack Trace
3. Recover (การดักจับและกู้คืนระบบ)
   recover คือฟังก์ชันบิวต์อินที่ใช้ กู้คืนระบบกลับมาจากการ panic เพื่อไม่ให้โปรแกรม Crash
   เงื่อนไขสำคัญ: recover จะทำงานได้ เฉพาะภายในฟังก์ชัน defer เท่านั้น 
   (หากเรียกในโค้ดปกติจะคืนค่า nil และไม่มีผลอะไร)

   การทำงาน: เมื่อเกิด panic และเข้าสู่ขั้นตอนการรัน defer ฟังก์ชัน recover()
   จะจับค่าข้อผิดพลาดที่ส่งมาจาก panic ไว้ได้ ทำให้โปรแกรมหยุดการลุกลามของ panic และกลับมาทำงานต่อตามปกติ

   Ex.
   func f() {
    defer func() {
        if r := recover(); r != nil {
            fmt.Println("กู้คืนจาก panic สำเร็จ:", r)
        }
    }()
    
    panic("เกิดปัญหาร้ายแรง!") // เมื่อเกิด panic จะวิ่งเข้า defer ด้านบน
   }

4. แนวปฏิบัติที่ดีในชีวิตจริง (Best Practices ใน Standard Library)
   บทความได้ยกตัวอย่างการใช้งานจริงจากแพ็กเกจ encoding/json ของ Go:
   
   -การใช้ภายในแพ็กเกจ: ในโค้ดภายในของแพ็กเกจ (Internal) ที่มีการเรียกฟังก์ชันซ้อนกันลึกๆ อาจใช้ panic
   เพื่อส่งข้อผิดพลาดด่วนย้อนกลับมาที่ฟังก์ชันระดับบนสุด (Top-level) ได้ เพื่อไม่ต้องคอยเช็ก if err != nil ทุกชั้น

   -API สำหรับภายนอก: ฟังก์ชันระดับบนสุดจะใช้ defer + recover ดักจับ panic 
   นำข้อผิดพลาดนั้นมาแปลงเป็นค่า error ปกติ แล้ว ส่งคืนกลับไปเป็น error value

   ปรัชญาของ Go: แม้ภายในแพ็กเกจจะแอบใช้ panic/recover ในการจัดการ Flow 
   แต่มุมภายนอกที่นักพัฒนาคนอื่นนำไปใช้ (Public API) จะต้องคืนค่าเป็น error ตามปกติเสมอ 
   ไม่ปล่อยให้ panic หลุดออกไปกระทบผู้ใช้งานแพ็กเกจ
